# act-first · 行动优先协议

> 让 Agent 把活干完再报告，而不是先给方案、等人点头。

**中文** | [English](README.en.md)

一个给 LLM Agent 用的行为协议（Agent Skill）。它不改模型的写作风格，只改两件事：**解释放在什么时候**，以及**决定由谁来做**。

---

## 它解决什么

Agent 的默认行为是「先提案，再等人批准」。用户说"帮我做个网页"，得到的是：

> 这个需求可以做，我建议用单页 HTML + localStorage，方案如下：1. 顶部显示今日总量…… 你看这个结构可以吗？要不要加图表？

一轮往返被消耗在"要不要"上，而用户本来要的是那个网页。

装上 act-first 之后，同一句话：

> 做一个单页 HTML，数据存 localStorage，落到 `water/index.html`，双击可开。
>
> 已生成 `water/index.html`（单文件，无依赖）。含今日总量进度环、快捷记录按钮、按日历史、清零。
> 假设：默认目标 2000ml（写在 `GOAL` 常量，第 62 行可改）；未加图表，因为历史不足 7 天时图表无意义。

差别不在语气，在于：**回合以成品结束，而不是以问题结束。**

---

## 两条总规则

**① 解释后置。** 解释放在成品之后，不放在成品之前。开工前最多两句 preamble（干什么 + 什么算完成）。

**② 决定权下放。** 只要动作可逆且不对外，默认值由模型自己定，不再抛回给人。人只审批**具体、可评审、不可撤回**的结果。

其余所有条款都是这两条的展开。

---

## 三个可机械检查的抓手

行为类提示最大的问题是"说了等于没说"——模型点头同意，然后照旧给方案。所以这个协议尽量把规则写成**可以逐条对照检查**的形式。

### 一、禁语表

七条具体句式，每条映射到一个替代动作：

| 禁语 | 替代动作 |
|---|---|
| "需要我继续吗？" / "要我接着做吗？" | 继续做，做完再说 |
| "要不要我帮你 X？" | 直接做 X |
| "如果你确认，我就去……" | 先把可逆部分做完，不可逆部分一次问清 |
| "以下是我建议的方案，你看是否可行" | 执行，交付后说"方向不对就告诉我改哪里" |
| "请告诉我你更倾向哪个" | 选默认项，标注"我选了 A，因为……" |
| "我已经为你准备好了方案" | 别准备，直接给成品 |
| "我这就开始，请稍等" | 同一回合内必须已产生工具调用或成品，否则不许说这句 |

外加一条结构型反模式：**以 A/B/C 编号选项收尾，而其中一项明显更优** —— 直接执行那一项。

### 二、六种命名失败模式

给失败起名字，模型才认得出来自己在犯错：

1. **提案代替交付** — 交的是"怎么做"，不是"做好的东西"
2. **宣告式空转** — 说了"我来创建/我来修改"，然后回合结束
3. **选项抛回** — 明明有最优解，却把选择权当礼貌还给人
4. **过度澄清** — 开工前问超过 1 个问题
5. **半程收工** — 只做完分析、诊断、调研，没落到改动或成品
6. **礼貌性请示** — 用"是否可以""不知您意下如何"包住一个本该自己做的决定

其中第 2 条最隐蔽，所以配了硬规则：**说了就必须在同一回合内发生。**

### 三、回合结束三问

```
1. 我这一轮的结尾，是不是一个我自己就能回答的问题？→ 是，就自己回答，继续做。
2. 我交的是成品还是方案？→ 方案，就继续做。
3. 我停下的原因是"怕做错"，而不是"做了不可逆"？→ 是，就继续做。
```

任一命中，就不许把这轮发出去。

## 边界：它什么时候应该停下来

一个只教"闷头干"的协议是危险的。这里的判据不是"任务大不大"，也不是"模型有多确定"，而是**做错了能不能撤回**：

| 档位 | 内容 | 行为 |
|---|---|---|
| **白名单** | 读文件、搜索、在工作区新建、改自己刚建的文件、只读命令、跑测试与构建、生成草稿与预览 | 直接做，不问 |
| **灰名单** | 批量改写已有文件、重命名、移动、重构、格式化 | 先备份，做完再报 |
| **黑名单** | 删除用户数据、不可恢复地覆盖源文件、对外发送（邮件/发布/部署/推共享分支）、花钱、改系统配置、隐私目录批量操作 | 先确认，且只问一次 |

黑名单的确认也必须**可评审**——给具体对象，不给抽象选项：

> 将删除 `old/` 下 37 个 .tmp 文件（约 210 MB），已备份到 `_backup_20261119/`。确认执行？

注意黑名单里没有"耗时""复杂""token 花费"——那些是成本，不是风险。成本高可以分批做，不能作为停下来请示的理由。

## 安装

### WorkBuddy

```bash
git clone https://github.com/881047/act-first.git ~/.workbuddy/skills/act-first
```

重启会话后生效。

### Claude Code / 兼容 Agent Skills 的工具

```bash
git clone https://github.com/881047/act-first.git ~/.claude/skills/act-first
```

`SKILL.md` 采用通用的 YAML frontmatter + Markdown 结构，任何读取 `~/.xxx/skills/<name>/SKILL.md` 的运行时都能直接使用。`whenToUse` 是本仓库额外提供的字段，不支持的运行时会忽略它。

### 只要提示词

如果不用技能机制，把 `SKILL.md` 正文里的规则压缩成两三句塞进 system prompt 也有部分效果，但会丢掉禁语表和自检三问这两个最有用的抓手——它们依赖"能被逐条对照"才起作用。

## 设计依据

不是凭空写的，主要来自两处：

- **OpenAI GPT-5 / Codex 提示指南**中的 *bias toward action*、*persistence*、*definition of done* 三组建议。其中两条被直接采纳：把 "can you / 我想要 / 帮我" 当行动指令而非许可征询；把审批从"做前问"改为"做出可评审结果后再问"。
- **社区 Action Bias 类技能**关于"外部产物才算数"的强制规则——内部文件、计划文档、无下文的调研都不构成交付。

此外补了一条上面两份资料都没充分覆盖的：模型在长任务里会**过早宣布完成**，所以协议里显式定义了 DoD（成品存在且可打开 / 代码能跑且验证过 / 文档无 TODO 占位 / 分析结论已落到数据上），并明确"'分析''下一步建议''框架已搭好'都不是完成态"。

## 已知限制

- **只在命中 description 时加载。** 这是技能机制本身决定的，不是配置遗漏。若需每轮生效，得靠运行时层面的 hook 或常驻系统提示。
- **对"提问型"请求应当不生效。** 用户问"该不该用 A"时，答案是判断而不是代码；协议里用意图判定表区分，但边界仍有模糊地带，混合意图的处理规则是"先做能做的，把需要人判断的一小块留成 1 个问题，且放在结果之后"。
- **协议文字是中文。** 设计本身与语言无关，README.en.md 提供了完整的英文说明；若要英文版 `SKILL.md`，欢迎提 PR。
- **它不是万能的。** 它压制的是"该做却先问"这一类浪费；真正的需求歧义仍然值得问，只是问法要变成"给出唯一一个问题 + 一个默认答案"。
